# 0001 — Versioned maintenance via changesets, installed via the skills CLI

Status: accepted · Date: 2026-08-04

## Context

The `gas-cityscape` skill previously lived only as a loose directory in `~/.agents/skills/`, unversioned: no release history, no way to tell which copy was current, no upstream an installed copy could refresh from. Any edit silently diverged installed copies.

## Decision

Adopt mattpocock's model wholesale, from `github.com/mattpocock/skills`:

- The skill ships from a git repo — `github.com/kotak-cloud/skills`, local clone `~/dev/kotak-cloud/skills` — in mattpocock's layout: `skills/<category>/<name>/SKILL.md` plus co-located `reference/` and `assets/`.
- **Versioning is repo-level via changesets**: every change adds `.changeset/<topic>.md`; the `Release` workflow (`.github/workflows/release.yml`) bumps the version and tags it on merge to `main`; `CHANGELOG.md` is generated by changesets, never hand-edited.
- **Installation is the `skills` CLI** — `npx skills@latest add kotak-cloud/skills` — the same mechanism mattpocock uses; updates via `npx skills update`.
- **Maintainers symlink** via `scripts/link-skills.sh` so a `git pull` updates installed copies.
- The skill itself documents this: it orients against whether its own copy is current, and points the onboarder at `github.com/mattpocock/skills` to install the skills it runs on.

## Consequences

- Installed copies can always be traced to a release tag; the onboarder checks staleness before running.
- The repo depends on Node + changesets for release automation; no publish step — the package is private, releases are git tags.
